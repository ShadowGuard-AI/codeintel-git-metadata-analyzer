A station log read watch by watch: author addresses counted, commit subjects and local branch names checked against their patterns, and a risk score added by kind.

Addresses Below the Cut Line

It reads a git repository. It counts author addresses from the log, one per line. An address counts as anomalous when its share of all commits falls below one minus the threshold. The default threshold is 0.9, so the cut line is a share below 0.1. It checks commit subjects against a pattern, and local branch names against a pattern, and it adds a risk score. That is the work, logged plain.

Subjects That Miss the Pattern

The commit check reads the subject line only. The body is never checked. The default pattern is ^[A-Z][a-z]+:\s.*, a capitalised word, a colon, then text. The branch check reads local branches only; remote branches are never checked. Its default pattern is ^(feature|bugfix|hotfix|release)/[a-z0-9-]+$.

Subjects Only, Bodies Never Checked

A message with a clean subject and a body that breaks the pattern passes. The website states the limit at full size, as the log does.

A Score That Counts Kinds

Email anomalies present: add 0.3. Invalid subjects present: add 0.2. Invalid branches present: add 0.1. Each outside tool with a non failure output: add 0.4. The cap is 1.0.

Caution, in signal red: the score counts kinds, not amounts. One odd address scores the same as half the history.

The outside tools are off by default. Bandit, flake8 and pylint run over the whole tree. Pyre runs only when a .pyre_configuration file exists. Missing tools are reported as text, not as findings. The report is written to the output file in five sections: risk score, author email analysis, commit message validation, branch name validation, and offensive tools analysis. Failure entries: a path that is not a directory ends at exit 1, a report that cannot be saved ends at exit 1, and an unexpected error ends at exit 1 with a logged trace.
